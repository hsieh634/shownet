# Shownet Travel OpenSpec Project

## Product intent

Replace the plugin-heavy WordPress commerce stack with an owned travel booking platform. Vietnam is the initial market. The platform supports both instant confirmation and supplier/manual confirmation products.

## Change workflow

Every major capability is developed through:

1. Proposal
2. Design
3. Specification
4. Tasks
5. Apply
6. Automated and manual verification
7. Review
8. Archive

## Specification language

- Normative requirements use MUST, SHALL, SHOULD, and MAY.
- Each requirement includes observable scenarios.
- Business state changes identify transaction and concurrency expectations.
- Out-of-scope behavior is explicit.
